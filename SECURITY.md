# Security boundaries and vulnerability reporting

This is an experimental security-scanning integration. Scan findings are untrusted evidence, not proof of exploitability; an empty report is not a security guarantee. Real-provider end-to-end compatibility and live detection quality remain unverified; no paid inference was initiated by the implementation agent.

## Intended boundary

The authenticated loopback Harness UI authorizes billable source transmission to the selected configured Harness provider. The agent tool has no start/validate operation. Workspace ownership is taken from the executing session registration for tool requests; UI requests use only registered workspaces and existing owned scan IDs. The HTTP API requires native Harness request authentication, loopback address/Host, a custom header and same-origin authorization for paid actions. Every Start/Validate and failed-history-clear request also requires a random 256-bit, per-runtime UI CSRF token obtained only from an authenticated, non-cacheable HTTP bootstrap/status response. The token is sent in a custom header and never appears in agent tool results, persisted records, exports or logs. A supplied `Origin` must exactly match the loopback Host; supplied Fetch Metadata must be `same-origin`. Missing browser-generated markers do not replace the token requirement, and cross-site, same-site, opaque and conflicting markers are rejected even with a valid token. The client restricts Fetch to `mode: 'same-origin'`, verifies its token with a read-only status preflight before enabling Start/Validate, and still requires explicit per-action consent.

Provider/model choices and the default, including optional reasoning effort, come from `sessionController.modelCatalog()`, the authoritative native Harness input-picker catalog. There is no adapter-list fallback. Before inference, configured-provider/native-catalog membership and resolved model identity are enforced and any explicit reasoning effort is validated. The bridge binds the exact provider/model and verifies the prepared adapter route. The activated Security dropdown was verified with configured options including GPT-6.1-Sol; it is not a reuse of the native input component.

Native Codex speaks Responses to a container-local loopback endpoint. Framed requests cross container stdin/stdout to the Host transport, where `harness-gateway.mjs` translates them to `llm.prepareCall` and the prepared adapter stream. Existing Harness adapters own provider access and authentication. The Host binds the scan UUID as native `GenerateOptions.sessionId`, stable within an operation and fresh for each scan/validation; the adapter generates required session-affinity headers such as `x-opencode-session`. This routing identifier is not a credential or a persisted chat session, and container requests cannot override it. The bridge does not read raw credentials, directly forward to a fixed DeepSeek endpoint or require a separate plugin API key. The scanner's local credential command emits a dummy gateway token, not a provider credential. Fresh container state has no ambient Codex login, Host home, external MCP configuration, proxy or tracing configuration.

Native engine tools execute only inside the container. The bridge translates local tool schemas/calls/results but never invokes Harness tools. Hosted external tools, remote background/storage and provider/model changes are rejected. A failed boundary check stops the operation; the bridge does not silently fall back to another provider/model. Native request/stream retries are disabled, but prepared adapters may retain their own retries. Sanitized failures, not raw adapter/provider error bodies, are exposed to the engine. Failures exposed to the engine contain only fixed allowlisted Harness categories or static bridge invariant messages. Local diagnostic classification transiently inspects own data-backed adapter messages within a 32,768-character limit, producing only fixed allowlisted provider code/type, standardized top-level request parameter, numeric tool index and rejection-rule enums. Arbitrary provider strings, schema paths, messages and stacks are not copied; getters are not invoked. Validated token/temperature controls are bound before immutable Harness call preparation, not changed afterward.

The Docker container has no external network, writable source, writable root image, added capabilities, privilege escalation, Docker socket or Host credential. It receives the approved workspace read-only, private writable report state and limited tmpfs scratch. Bubblewrap is a nested sandbox; the outer Docker boundary still applies even when the engine requests broader tool permissions. Custom seccomp allowances permit only the documented namespace/mount setup and do not grant outer kernel capabilities.

Repository code and model output can be malicious. Executing tests, parsers or dependency code inside the scanner can exploit bugs in native components or the kernel; Docker is not a substitute for a separate VM for strongly adversarial repositories. Do not scan untrusted code on a machine holding high-value secrets merely because its source mount is read-only. Keep Docker, its kernel and scanner dependencies patched.

## Protocol and operational limits

- Consent permits source and findings to leave the machine for the selected provider under its configured adapter routing; it does not authorize arbitrary publication or source mutation. Review provider configuration and data policies before consenting.
- Only POST `/responses` for the bound model is accepted from the engine. Explicit input history is required; `previous_response_id` is unsupported. Opaque replay requires intact consecutive cached assistant groups, and missing, modified or evicted groups fail closed. Matching tolerates only transport status, native null optional reasoning `content`/`encrypted_content`, and omitted empty output-text annotations. Identifiers, text, arguments, nonempty and unknown fields remain exact; opaque adapter state is restored only from the attributable local cache.
- The bridge supports text and local function/custom tools with automatic tool choice only. Multimodal and hosted tools are unsupported. JSON Schema requests become instructions, not guaranteed strict provider-native schema mode. Catalog membership alone does not establish adapter/model compatibility.
- Transport limits are four concurrent requests, 100 requests per operation, 16 MiB request JSON, 64 MiB response and 180 seconds per model request. The bridge bounds JSON/replay state at 64 MiB and caches at most 256 response groups. Deadline/request/concurrency/size ceilings bound operations, not dollar cost or every adapter retry. Cancellation cannot undo charges for a request already accepted by the provider.
- Docker creation has a 30-second managed-client timeout, but daemon-side creation can outlive the client. Durable, label-verified leases are reconciled at startup and every 30 seconds; cleanup removes immutable container IDs only after verifying the lease label. Uncertain absent `creating` leases remain tombstones indefinitely, and legacy unlabeled containers are not automatically removed. Cleanup/grace can exceed the scan deadline; interrupted runs are not automatically resumed.
- Export is report-only and requires no model inference, but JSON/CSV/SARIF may disclose source, paths and vulnerabilities. Do not commit local engine state or generated findings to a public repository without reviewing them.
- Engine source is mounted directly read-only; unsupported symlinks/submodules/worktree metadata outside the registered path are not automatically granted extra mounts.
- Engine state is kept in private directories outside Git worktrees. Durable Harness records/history also contain potentially sensitive findings. Authenticated UI confirmation can remove an exact snapshot of workspace-owned failed history records only after their task/lease cleanup has finished; it preserves other statuses and deletes no private engine files. Agents cannot invoke this operation. A storage I/O failure can leave partial record deletion; the UI refreshes before retry. Automatic artifact retention/deletion is not implemented; remove files only after tasks and containers are stopped, using reviewed absolute paths.
- New scans retain at most 128 strict-schema diagnostic entries plus an overflow count. Host logging and local diagnostic downloads contain only fixed stages, local UUIDs, sizes/counts, durations, numeric controls and allowlisted failure codes/optional trusted numeric HTTP status. They exclude source, schema/property names, credentials, raw bodies/headers/URLs, replay, provider messages/stacks/request IDs and hashes. Logging callbacks cannot change inference outcomes. Diagnostic version 2 also records bounded fixed-enum rejection evidence and error-message availability/length/truncation, without retaining the message. Local protocol failures additionally retain a fixed `protocolInvariant` enum identifying the exact bridge rejection; its invariant and stage also appear in the scan error when it causes the model-request failure. These are locally authored constants, not request/provider text, and do not require private capture. Engine failures likewise produce only fixed ownership/create/cleanup/protocol/unclassified hints, never error text or state paths. SDK-message status prefixes are kept in `reportedHttpStatus`, separate from trusted `upstreamStatus`, and never change inference behavior or the trusted failure reason. Message-derived hints are not proof; unknown errors stay unclassified. Old records cannot recover discarded messages. `INVALID_REQUEST` without trusted status remains ambiguous at the transport boundary.
- Exact adapter error text is captured only with an explicit additional per-scan UI opt-in; it defaults off, resets on each action/workspace/model change, and never substitutes for paid source/inference consent or authenticated panel CSRF. Only the first adapter rejection is captured, with at most 65,536 UTF-8 bytes each for its own original and nested messages. The exclusive-create `0600` file is a sibling of the scanner's mounted state, under the `0700` private root outside Git. No raw text enters the scan table, normal logs, diagnostic downloads, reports or engine frames; only capture status is stored. The UI displays its private local path. There is no raw-error download API or agent-tool operation. Captured errors can echo source, secrets, provider metadata and credentials; protect them like sensitive engine state. Capture failure does not alter inference, and no additional provider request is made. Old discarded errors remain unrecoverable; capture cannot restore transport metadata the adapter never supplied. Files remain until separately reviewed manual removal.
- The full Host process, configured adapters and its filesystem/tool access are trusted. Same-origin UI authorization is not an unforgeable human-presence guarantee against an attacker or an unrestricted agent that already controls the Host/browser. Do not expose the local Harness endpoint or permit untrusted extensions to operate it.
- The engine model catalog is an original minimal authored template, not the removed third-party copied prompt catalog. Its planning hint is not a guarantee of provider reasoning behavior; Harness owns the selected provider reasoning configuration. No licensing claim is made for the removed copied prompts.
- The latest serial offline suite passed all 162 tests, including real native scanner/local-tool/opaque-replay roundtrip through a synthetic Harness adapter, four-block native reasoning/text/multiple-tool replay normalization, strict rejection of edited or incomplete history, and fixed local protocol-invariant persistence/privacy, failed-history deletion authorization/races, diagnostic sanitization and OpenCode session-header generation through the shipped Harness runtime/adapter/wrapper. The rebuilt Host runtime was activated and its revision verified through read-only status without inference. The earlier activated runtime/picker was verified; the latest client changes require bundle reload and were tested in the stateful UI harness, not re-verified in the live GUI. This does not establish real-provider compatibility, live detection quality or parity against known-vulnerability and negative-control repositories.

## Report vulnerabilities

Public repository: [TheSethRose/dsh-security](https://github.com/TheSethRose/dsh-security). Use GitHub's private vulnerability reporting when enabled, or contact the repository owner privately before disclosing exploit details. Do not post API keys, raw sensitive reports, private repository contents or working exploit credentials in public issues. Include the plugin revision, locally built engine image ID, Harness/Docker/kernel versions, the configured provider/model (without credentials), the boundary affected and a minimal non-sensitive reproduction.

If isolation or provider routing fails, stop the scan/plugin. Do not enable privileged mode, writable source, unconfined seccomp, provider/model fallback or silent kernel-policy relaxation as a workaround.
